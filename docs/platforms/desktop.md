## 제품 구조

목표는 **기존 self-host를 Windows에서 앱처럼 쓰는 것**입니다. 서재 한 곳을 여러 화면에서 이용합니다.

```text
서버가 없는 사용자: Windows 앱 → 앱에 포함된 기존 self-host → DB·원본 파일
                                      ↑
                             다른 기기의 브라우저

서버가 있는 사용자: Windows 앱 / 브라우저 → 사용 중인 self-host → DB·원본 파일
```

- 저장·가져오기·수집기·독서·AI/TTS·백업은 기존 공통 서버를 재사용합니다.
- 다른 기기 접속은 같은 서버의 주소와 로그인으로 처리합니다. LAN·터널·Tailscale 같은 연결 방식은 저장 모델과 독립적입니다.
- 서재 이전에는 백업·복원을 사용합니다. 두 서버에 따로 생긴 변경을 자동 병합하지 않습니다.
- 기존 브라우저 캐시와 서버 사이의 `/api/sync`, `/api/sync/events`는 계속 필요합니다. 서버 간 복제와 구별합니다.

**구현 사실:** 내장 서버 자동 시작·공유와 기존 서버 주소 선택이 있습니다. 선택한 기존 서버는 다음 앱 시작에 별도 WebView 창에서 해당 서버의 웹 화면과 로그인으로 열립니다. 앱의 로컬 서재는 그대로 보관되며 두 서재는 자동으로 합쳐지지 않습니다.

**외부 서버 버전 조건:** 구버전 웹 화면은 Tauri의 전역 객체 때문에 자신을 네이티브 앱으로 오인할 수 있습니다. 추가 검토 수정본은 서버가 제공하는 `index.html`의 `boaa-desktop-webview=browser-v1` 선언을 확인한 뒤 창을 엽니다. 선언이 없는 서버는 웹 화면까지 업데이트하거나 일반 브라우저로 접속해야 합니다.

## 필요성과 비용 판단

| 작업                                           | 판단                               | 근거                                                                                             |
| ---------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------ |
| 내장 self-host의 시작·종료·설치·데이터 보존    | 필요                               | 서버를 별도 설치하지 않고 로컬에서 사용하기 위한 앱 경계                                         |
| 기존 서버 직접 접속                            | 구현, Windows 기본 검증 통과       | 이미 서버가 있는 사용자는 같은 서재를 그대로 이용해야 함                                         |
| 같은 서버의 원격 접속                          | 필요                               | PC를 켜 두고 다른 기기에서 읽는 요구                                                             |
| 기존 백업으로 자료 이전                        | 필요                               | 서버를 옮기는 일회성 작업                                                                        |
| 독립 서버 간 원본·주석·삭제의 양방향 자동 복제 | 현재 범위에서 제외                 | 두 서재를 독립 편집해야 하는 요구가 없고, 모든 새 데이터 종류마다 충돌·삭제·재시도를 구현해야 함 |
| 대용량 IndexedDB를 별도 네이티브 저장소로 교체 | 현재 데스크톱의 선행 과제에서 제외 | 실제 자료는 기존 서버의 DB·파일 저장소가 담당                                                    |

## 빌드와 배포 범위

네이티브 빌드 방법은 [빌드 안내](native-build-guide-ko.md), 배포 후보의 검증 범위와 제한은
[릴리스 안내](../releases/0.1.1-beta.1.md)를 참고합니다. 운영 데이터 이전과 백업·복원은
공통 서버의 계약을 사용합니다.
