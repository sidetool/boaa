# UI 전환 후 동작·상태 경계 검토

검토 기준: `ca5145e`, `release/server-beta4`. 검토 모델은 Astra xhigh, 구현 모델은 Astra medium이다.

## 범위와 판정 기준

- 스트리밍 작품, 저장한 회차, 서재 항목의 동일성: 휴지통·복원·영구 삭제·다운로드만 삭제·읽기 진행의 연결.
- 최근 읽기와 책장: 읽은 시점과 메타데이터 수정 시점의 분리, 이동·즐겨찾기·태그·다중 선택의 일관성.
- 화면과 비동기 작업: 탐색·목록·독서·설정 전환, 취소·실패·늦은 응답, 반복 조회와 불필요한 렌더링.

기존 아키텍처 문서와 사용자에게 보이는 명칭을 기준으로 의도를 확인한다. 의도된 동작은 유지하며, 코드로 경로를 확인하거나 재현한 결함과 추가 확인이 필요한 가설을 구분한다. 성능 문제는 실제 반복 작업이나 측정 근거가 있을 때만 수정 대상으로 삼는다.

이번 검토는 현재 동작의 결함을 찾는 작업이다. 원인 커밋까지 확인하지 않은 항목을 모두 UI 전환으로 생긴 회귀라고 단정하지 않는다.

공개 문서와 테스트에는 가상의 작품·소스만 사용한다. 운영 데이터와 비공개 확장은 변경하지 않는다. 이번 검토·구현은 다음 베타 작업 트리에서 진행하며 운영 배포와 릴리스 발행은 별도 단계이다.

## 진행 상태

1. 분야별 독립 검토 완료: P2 8건, P3 1건. 확인된 P1은 없다.
2. 기존 테스트 기준선: 서재·책장·탐색 상태 28개 파일/218개 테스트, 독서·만화·발견·검색 화면 131개 파일/750개 테스트 통과.
3. 문서화한 9개 결함을 Astra medium으로 구현하고 회귀 검증했다. Astra xhigh의 독립 재검토에서 추가로 재현한 삭제 경계 2건도 보완했다.

기존 테스트 통과만으로 동작이 올바르다고 판정하지 않았다. 각 분야 문서의 재현과 한계를 함께 확인해야 한다. 모든 화면·플랫폼·실서버 조합을 전수 검증한 결과는 아니다.

## 유지할 의도

- `다운로드만 삭제`는 작품을 서재에 남긴다. `휴지통`은 서재 항목을 숨기며 `영구 삭제` 뒤 옛 이력으로 자동 복구하지 않는다. 원격 사이트의 작품 자체를 삭제하는 명령은 아니다.
- 한 작품의 `책장 이동`과 다중 선택의 `책장에 추가`는 서로 다른 명령이다.
- 미독 작품도 정렬에는 남기되, 메타데이터 편집을 실제 독서로 취급하지 않는다.
- 공유 표지 요청은 다른 소비자가 남아 있으면 계속한다. 마지막 소비자의 취소와 실제 작업 제한을 일관되게 처리한다.

## 성능 기준선

기존 `7014c93` 웹 빌드의 초기 정적 그래프는 JS 2,088.8 KiB(전송용 gzip 602.0 KiB), CSS 226.4 KiB(gzip 39.0 KiB)였다. 지연 로딩 JS는 4,003.2 KiB다. 저장소의 과거 권장 예산을 넘지만, 이것만으로 사용자 체감 성능 저하나 UI 이전의 인과관계를 확정하지 않는다. 구체적인 불필요 요청·작업은 개별 재현으로 판단한다.

## 최종 통합 검증

[독립 재검토 결과](ui-migration-final-verification.md): 요청 범위에서 확인된 미해결 P1/P2 없음. 이 결론은 모든 플랫폼·실제 사용자 환경에 문제가 없다는 뜻은 아니다.

- 관련 UI/서재/소스/캐시/클라이언트 테스트: **197개 파일, 1,675개 통과**.
- 실제 임시 PostgreSQL 통합: **2개 파일, 5개 통과**, skip 없음. 단일 영구 삭제·휴지통 비우기 뒤 전체 서재 복구와 책장 원자적 저장 실패/동시 수정/계정 격리를 포함한다.
- 웹·서버·스크립트 타입 검사, 변경 코드 46개 파일 ESLint·포맷, 공유 계약 경계 검사 통과.
- 신규 파일까지 포함한 공개 소스 경계 검사 4,519개 파일 통과.
- 웹 프로덕션 빌드, 서버 번들 및 최소 서버 프로덕션 검사 통과.
- 검토자가 기록한 구현 diff SHA-256과 최종 빌드 대상 구현 diff가 일치한다.

최종 웹 초기 정적 그래프는 JS 2,095.3 KiB(gzip 604.0 KiB), CSS 226.4 KiB(gzip 39.0 KiB)다. 이번 수정으로 초기 gzip JS가 약 2.0 KiB 증가했다. 과거 권장 예산 초과는 유지된다. 이번에 재현·수정한 성능 결함은 표지 요청 수명/동시 실행 제한이며, 초기 로딩 전체를 최적화했다고 주장하지 않는다. 초기 번들 분할, 대규모 서재 가상화, 실제 모바일 내비게이션·다중 탭 부하·실서버 체감 지연 측정은 별도 후속 측정 항목이다.

모든 검증은 합성 데이터 및 격리된 테스트 DB로 진행했다. 운영 데이터·비공개 확장을 수정하지 않았고, 운영 배포·버전 태그·릴리스 발행은 수행하지 않았다. 변경은 다음 베타 브랜치 `release/server-beta4`에 포함한다.

## 남은 검토·검증

위 9건의 결함 구현은 완료됐다. 아래 항목은 확인된 미수정 결함이 아니라, 아직 확보하지 못한 검증 증거와 별도 조사 범위다. 자동 테스트 1,680개에는 기존 회귀 테스트가 포함되며 실제 모바일 사용자 흐름 1,680개를 검증했다는 뜻이 아니다.

1. **실제 브라우저에서 주요 사용자 흐름 연결 확인.** 격리된 서버·합성 작품으로 탐색 → 스트리밍 → 회차 저장 → 서재 이동 → 휴지통 → 복원 → 영구 삭제 → 새로고침을 UI 조작으로 끝까지 실행한다. 모바일 크기에서 최근 읽기 순서, 완독 필터, 작품 개수, 뒤로가기, 오류·재시도와 확인창이 같은 상태를 보여 주는지 확인한다. 현재 코드를 사용하는 실제 Android Chrome/PWA와 다른 브라우저는 별도 장치 검증 범위다.
2. **실제 브라우저의 동시성·복구.** 두 탭에서 삭제/기록 저장/책장 이동을 교차하고, 계정 전환·오프라인·연결 복구·페이지 재시작 뒤 상태를 대조한다. 현재 합성 테스트는 해당 interleaving을 재현하지만 실제 다중 탭의 스케줄링·저장소 이벤트 전체를 실행하지 않았다.
3. **측정 기반 성능 후속 조사.** 초기 로딩의 JS 실행·긴 작업, 큰 합성 서재의 스크롤·필터 지연과 메모리, 차가운/따뜻한 캐시에서 표지 응답 및 빠른 화면 전환 후 실제 남은 네트워크 요청 수를 측정한다. 현재 번들 크기만으로 코드 분할이나 가상화가 필수라고 결론 내리지 않는다. 표지 캐시의 작업 수 제한 검증도 실제 전송 취소·서버 처리 종료 측정을 대신하지 않는다.
4. **이번 집중 범위 밖의 UI 흐름.** TTS·AI·OCR·클라우드 동기화·백업 등 모든 기능의 UI 이전 전후 동작을 전수 대조하지 않았다. 실제 모바일 키보드/포커스, 스크린리더, 밝은 테마, 다른 브라우저의 접근성·레이아웃 전체도 미검증이다. 핵심 흐름 검증 후 사용 빈도와 사용자 제보에 따라 별도 점검 범위를 정한다.

운영 배포·베타 릴리스 발행도 아직 수행하지 않았다. 다음 검증에서는 1·2의 실제 UI 연결 흐름을 먼저 확인하고, 3의 측정 결과로 추가 최적화 범위를 결정한다. 추가 코드 검토는 Astra xhigh, 필요한 구현은 Astra medium으로 이어간다.
