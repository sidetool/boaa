## Residual findings resolved during verification

1. **P2: delayed journal replay could overwrite a purge tombstone.** Recovery originally captured all preferences once, then saved visits sequentially. A purge committed while an unrelated visit was saving could be followed by the target's stale write, restoring its history and library card. A real IndexedDB-backed synthetic probe reproduced this. [Atomic visit replay](../../src/external-sources/local-state.ts#L272) now compares current timestamps inside the write transaction and returns the authoritative record. Recovery uses that record for its returned projection as well. An atomic replay failure retains the checkpoint and fails the load instead of presenting stale history. The permanent [interleaving regression](../../src/features/external-sources/purged-source-library.test.ts#L195) verifies persisted and projected state.

2. **P2: an interrupted cleanup could replay the previous hosted account's journal into the current account.** Shared-state hydration replaces links, subscriptions and preferences, while device receipts and scoped journals survive. Draining every receipt through journal recovery therefore imported account A's pending history into account B after a crash and account switch. A real-store probe reproduced that result. [Receipt cleanup](../../src/features/external-sources/source-work-history.ts#L88) now selects only the active scope and directly acknowledges old visits for that work, without replaying them into shared state. The [account-switch regression](../../src/features/external-sources/purged-source-library.test.ts#L259) also switches back and verifies that the old receipt can finish without resurrecting the work.

Both probes failed before their corresponding corrections and pass as permanent regressions. Temporary review probes were folded into the lifecycle test file and removed. The existing receipt object store was confirmed in the baseline; this change does not introduce an IndexedDB version migration.
