# 작품 번역 (서버 웹/PWA)

기본 상태는 **사용 안 함 / 수동 시작 / 한국어 번역**이다. 관리자 계정으로 설정 → 작품 번역에서 엔진, 모델, 키를 저장하고 기능을 켠다. TXT·Markdown·EPUB 및 텍스트 소스 스트리밍에서 리더 더보기 → 작품 번역으로 시작한다. 데스크톱/정적 웹/회원 계정에는 노출하지 않는다.

## 키와 설정

- Gemini API, Google Cloud Vertex AI 서비스 계정 JSON, HTTPS OpenAI 호환 Chat Completions API를 지원한다. JSON 출력이 가능한 텍스트 모델 ID를 직접 입력한다.
- 키 저장은 브라우저 → 인증된 서버 API → AES-256-GCM 암호화 저장이다. 서버의 기존 `provider-secret-key`/`PROVIDER_SECRET_ENCRYPTION_KEY`를 재사용하며 TTS/화자 분석 키와 별도 테이블·AAD로 분리한다. 저장된 원문 키를 반환하는 API는 없다.
- 키 파일은 64KiB 이하로 제한한다. 선택 취소·제공자 변경·화면 종료 뒤 늦게 끝난 파일 읽기는 버린다. 입력값을 브라우저 저장소에 쓰지 않는다.
- Vertex의 프로젝트를 비우면 서비스 계정 `project_id`, 리전은 `global`을 사용한다. 키 저장은 IAM/모델 접근 확인을 의미하지 않는다.
- 일일 사용량 제한은 없다. 원문 문자 수(재시도 포함)는 참고용으로 집계하며 실제 토큰 청구액은 제공자에서 확인한다. 예전에 저장한 문자 한도도 더 이상 적용하지 않는다.
- 설정 저장은 revision 충돌을 검사하고 진행 작업을 중단한다. 키 교체·삭제도 같은 계정 잠금 안에서 해당 엔진 작업을 중단한다. 원문이나 기존 TTS 설정은 바꾸지 않는다.

## 처리와 읽기

- 번역 시작·진행 확인·중지·원문 전환은 우측 상단 더보기 → 작품 번역에서 한다. 읽는 동안 번역 전용 표시를 본문 위에 띄우거나 본문 여백을 추가하지 않는다. 기존 리더 메뉴·시트·테마 스타일을 사용한다.

- 한 화를 하나의 작업으로 저장한다. 기본 요청 크기는 6,000자, 긴 문단도 상한 안에서 분할하며 Unicode surrogate pair를 보존한다. 공백 문단은 요청하지 않는다.
- 출력 문단 ID·순서·개수·비어 있지 않은 텍스트·응답 크기를 검증한 뒤 저장한다. 긴 문단의 조각은 모두 완료된 후 한 문단으로 표시한다. 원문 JSON/문단 ID/읽기 기록/표지를 교체하지 않는다.
- 서버 BullMQ 작업은 기존 worker에서 실행한다. 별도 대형 이미지가 필요하지 않다. 업데이트 maintenance/drain에도 번역 큐를 포함한다.
- 기본 동시 요청 1개(최대 3), 재시도 3회, 초기 대기 2초, 요청 제한 120초. 지수 백오프와 jitter, `Retry-After`, 최대 자동 대기 10분을 적용한다. 인증 오류는 자동 재시도하지 않는다. 숨은 생성 SDK 재시도는 없다.
- 원문 revision/소유권/삭제 상태/실행 ID를 저장 전 재검사한다. 취소 또는 이전 실행의 늦은 결과는 반영하지 않는다. 중간 실패를 다시 시작하면 저장된 문단을 재사용한다. 프로세스 종료 직전 제공자에서 생성됐으나 DB에 저장되지 않은 조각은 재요청될 수 있다.
- 동일 계정·작품/회차·원문 hash·엔진/모델/목표 언어/문체/용어집 조합은 중복 작업을 만들지 않는다. 재접속은 기존 결과를 조회하며 상태 조회 자체로 합성을 요청하지 않는다.
- 자동 번역은 원문 언어를 확인할 수 있고 목표 언어와 다를 때만 시작한다. `und`·언어 미설정·짧은 텍스트·라틴 문자만으로 불확실한 경우에는 수동 확인을 받는다.
- 번역문은 스크롤 리더에 표시한다. 완료된 문단부터 보여 주며 미완료 문단은 원문이다. 원문/번역 전환 및 긴 번역문에서 행 높이를 다시 측정한다. 번역의 문자 offset으로 원문 인용/하이라이트를 저장하지 않는다.
- 수동 번역은 이번 화만 시작한다. 다음 화 준비는 설정 → 작품 번역 → 작품을 열면 자동 번역 아래의 ‘다음 화 미리 번역’ 토글로 제어하며, 켜면 준비할 화 수(1–3)를 정한다. 자동 번역을 끄면 다음 화 준비도 실행하지 않는다. 다음 준비는 현재 화 완료 후 보이는 리더에서만 시작한다. 저장된 작품은 설정한 최대 3화, 소스 스트리밍은 인증된 소스 port로 확보할 수 있는 바로 다음 1화를 준비한다. 다음 회차를 읽음 처리하거나 다운로드 서재에 추가하지 않는다. 이미 서버가 수락한 작업은 화면을 닫아도 끝날 수 있으며 ‘번역 중지’로 중단할 수 있다.

## 이번 구현의 경계

- 듣기·검색·인용은 원문 기준이다. 듣기 시작 시 화면도 원문으로 돌아간다. 번역 음성, 번역문 검색/주석 및 페이지 넘김 번역은 아직 제공하지 않는다.
- 설정은 계정별 한 묶음이며 공통 용어집/문체를 지원한다. 작품별 용어집, 회원별 번역 권한/예산, 제공자별 프로필 여러 개, 토큰/금액 계측은 후속 범위다.
- 부분 결과는 검증된 요청 단위로 표시한다. 모델의 미완성 JSON 토큰을 화면에 바로 보여 주지 않으며 진행 상태는 2초 간격 순차 조회한다.
- 실제 유료 제공자 호출 없이 합성 fixture로 검증했다. 제공자별 모델 호환성, IAM과 실번역 품질은 운영 키를 설정한 후 작은 회차로 확인해야 한다.

## 저장과 운영

추가 마이그레이션: `0061_text_translation.sql`, `0062_title_translation.sql`.

테이블은 `translation_settings`, `translation_credentials`, `translation_jobs`, `translation_daily_usage`다. 결과와 원문 snapshot은 작업에 함께 저장한다(한 회차 최대 50만자/1만 문단). 계정 삭제 시 연쇄 삭제한다. 저장 작품은 book FK와 revision으로 보호하고, 스트리밍은 계정별 snapshot으로 보호한다. 서버 DB 백업과 기존 암호화 master key를 함께 보존해야 복원 후 키를 사용할 수 있다.

API는 모두 관리자 인증을 요구한다.

- `GET/PUT /api/translation/settings`: 설정, 키 저장 여부, 오늘 사용량
- `PUT/DELETE /api/translation/credentials/:provider`: 키 저장/삭제
- `POST /api/translation/jobs`: 조회 전용 또는 화 번역 요청
- `GET/DELETE /api/translation/jobs/:id`: 결과/진행 조회 또는 취소
- `DELETE /api/translation/cache`: 해당 계정 번역 캐시 삭제(원문 보존)

## 검증

- `pnpm exec vitest run apps/server/src/translation apps/server/test/translation.integration.test.ts src/features/translation src/ui-next/settings/pages/TranslationPage.test.tsx`
- `node scripts/translation-ui-smoke.mjs`: 실제 Chromium, 390/1440px, 실제 설정 목록에서 번역 탭 진입·HTTP 클라이언트·리더 더보기 메뉴·가상 스크롤 리더, mock API. 키 저장, 수동 동의, 부분 결과/완료, 원문 복귀, 화면 폭 변경과 회차 처음/끝 이동 후 긴 문단 겹침·하단 회차 버튼 침범·가로 넘침, 번역 전후 본문 여백 유지와 별도 오버레이 부재 확인. 스크린샷은 `/tmp/boaa-translation-smoke/`에만 기록한다.
- PostgreSQL 통합 검증은 임시 DB에서 암호화, 권한/계정 경계, 중복 억제, 실패 재개, 취소/원문 교체 fence, 사용량 동시 집계을 확인한다.
- 실제 휴대폰 OS, 유료 API 합성, 운영 서비스 배포는 이 검증에 포함하지 않는다.

요청 스키마는 [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output) 및 [Vertex 구조화 출력](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/multimodal/control-generated-output)을 참고한다. 모델마다 지원하는 출력 모드와 사용 권한이 다를 수 있다.

### 2026-10-19 배포 후 발견과 재검증

- 설정 페이지 자체는 있었지만 실제 설정 내비게이션의 콘텐츠 그룹에서 `translation` 항목을 빠뜨려 진입할 수 없었다. 그룹에 항목을 연결하고, 기능이 비활성인 초기 상태에서도 서버 설정 목록에 나타나는 회귀 테스트를 추가했다. 수정 전 해당 테스트가 실패하는 것도 확인했다.
- 브라우저 검증을 단독 번역 페이지에서 전체 설정 목록 진입 경로로 바꿨다. 390/1440px에서 키 저장과 활성화, 더보기 수동 번역, 결과 표시, 원문 복귀를 확인했다. 820/1180px로 폭을 변경하고 회차 처음과 끝을 반복 이동하는 검사도 추가했다.
- 재검증 중 한 번 데스크톱의 끝 이동 직후 행 겹침이 관측됐다. 이후 동일 흐름 2회와 폭 변경을 포함한 강화 검사에서는 재현되지 않았다. 원인이 확정되지 않았으므로 해결 완료로 간주하지 않으며, 운영에서 발생하면 별도로 추적해야 한다. 이번 메뉴 연결 수정은 리더의 배치 알고리즘을 바꾸지 않는다.

### 다운로드 회차 추가와 번역의 원문 경계

작품 전체 revision은 다른 회차를 추가 다운로드할 때도 바뀐다. 이미 시작한 번역과 저장 결과는 작품의 소유권·삭제 여부·회차 존재를 확인하고, revision 값과 관계없이 해당 회차의 문단 ID/순서/원문 전체를 작업 snapshot과 비교한다. 다른 화만 추가됐다면 계속 사용할 수 있고, 실제 번역 대상 원문이 바뀌거나 회차가 삭제되면 차단한다.

새 저장 작품 요청은 리더가 읽은 `chapterTextHash`를 함께 보낸다. 작품 revision이 앞서 바뀌었어도 그 revision이 같은 작품에 속하고 회차 hash가 일치해야만 현재 원문으로 진행한다. 다음 화 준비는 다음 화 자체의 hash를 사용한다. 스트리밍은 기존 인증된 본문 snapshot 경로를 유지한다. 실제 유료 API 호출 없이 PostgreSQL 통합검사에서 회차 추가 중 작업 완료, 기존 결과 재사용, 실제 원문 교체·삭제·다른 계정 차단을 검증한다.

### 원문·작업 수명 검토

[번역 견고성 검토](reviews/text-translation-robustness.md)에 공통 불변조건, 수정 전 실패 재현, 임시 PostgreSQL/리더 hook 회귀와 미검증 범위를 기록했다. 새 캐시 hash는 저장 작품과 스트리밍 snapshot을 구분하며, 기존 hash의 작업은 같은 계정·작품/회차·문단·profile·`book_id`일 때 ID와 부분 결과를 그대로 재사용한다. 원문 최종 검증, 최종 결과와 완료 상태는 하나의 계정/작품 잠금 트랜잭션으로 저장한다.

리더는 계정 client·repository·저장/스트리밍·회차/원문·설정 revision을 공통 세션으로 묶는다. 늦은 설정/캐시 조회가 최신 설정이나 수동 동작을 덮지 못하며, 숨김·원문 전환·회차 이동 뒤 아직 접수되지 않은 다음 화 요청은 보내지 않는다. 취소 API 실패를 취소 성공으로 표시하지 않고, 성공 후 상태 재조회가 끊겨도 다시 조회한다. UI 디자인과 배치는 변경하지 않았다. 이 검토의 수정은 운영에 배포하지 않았다.

## 소스 작품 제목 번역

- 설정 → 작품 번역의 ‘작품 제목도 번역’은 기본 꺼짐이다. 전체 번역 사용은 켜야 하지만 본문의 자동 번역과는 독립이다. 기존 서버 저장 키·제공자·모델·언어·용어집을 사용한다.
- 홈 소스 카드, 탐색 카드, 소스 작품 목록/상세에 표시만 적용한다. 원제, 소스 식별자, 검색·다운로드·저장 메타데이터는 바꾸지 않는다. 번역되면 상세에 원제도 남기며 실패·대기 중에는 원제를 표시한다. 회차명·폴더명은 대상이 아니다.
- 화면에 접근한 카드를 250ms 동안 모아 최대 24개(제목당 500자)를 한 번에 요청한다. 동일 제목과 이미 완성된 결과는 제외한다. 제목 묶음은 본문의 문단 크기 설정과 독립으로 한 번의 제공자 호출에 전달한다. 결과 조회는 합성을 다시 요청하지 않는다.
- 제목 작업도 기존 번역 큐·재시도·계정 격리·취소 경계를 사용한다. 현재 회차보다 낮은 우선순위로 처리하고 제목 작업 대기는 계정당 두 묶음까지 허용한다. 이것은 작업 동시성 제어이며 일일 사용량 제한이 아니다.
- `POST /api/translation/titles`와 `translation_titles`가 계정·원제 해시·번역 프로필별로 기존 작업의 결과를 참조한다. 목록 순서나 페이지가 바뀌어도 재사용한다. 설정/키 변경 시 늦은 결과를 차단하고, 원제 변경이나 번역 프로필 변경은 별도 캐시다. 결과 전체 삭제·계정 삭제 시 함께 삭제된다.
- 짧은 제목은 언어를 확정하기 어려워 명백한 목표 언어와 숫자만 있는 제목은 로컬에서 제외하고, 나머지는 제공자에게 같은 언어라면 유지하도록 지시한다. 고유명사와 번역 품질은 모델에 따라 다르다.
- 실패한 유료 작업은 단순 목록 조회로 무한 재시도하지 않는다. 키/설정을 수정하거나 번역 캐시를 삭제하면 다시 시도할 수 있다. 브라우저 캐시는 계정 API별 메모리에만 유지한다.
