# 독서·듣기 사용성 검토

## 서버·웹 beta.8의 주요 변경

| 사용 흐름 | 변경 사항 |
| --- | --- |
| 앱 열기와 검색 | 로그인 화면은 리더 코드를 지연 로드한다. 서재는 기기 음성 확인이 끝나기 전에 열린다. 통합 검색에서는 서재 결과를 30개씩 볼 수 있고, 작품에서 돌아오면 검색어·결과 페이지·스크롤 위치와 포커스를 복원한다. |
| 회차 읽기 | 본문을 먼저 열고 회차별 화자·음성 정보를 따로 읽는다. 회차 끝에서 새 제스처로 한 화씩 이동한다. 검색 결과로 이동하면 낭독 중에도 선택한 문단을 볼 수 있다. EPUB 각주와 선택 도구가 알림·재생 버튼을 가리는 경우를 줄였다. |
| 듣기 | 저장 음성에도 현재 배속을 적용한다. 문단 이동과 연속 재생에서 수면 타이머의 남은 시간을 보존한다. 음성 엔진 연결이 끊어져도 같은 계정·본문 버전·목소리로 완성한 음성을 재생할 수 있다. |
| 책장과 다운로드 | 책장에 담은 구독 작품의 수를 집계한다. 모바일에서 회차별 저장·읽음 상태를 확인하고, 작품별로 대기열을 접거나 실패한 다운로드를 다시 시도할 수 있다. 기존 기기의 미완료 대기열을 복원할 때 회차 식별자와 버전을 대조한다. |
| 가져오기와 복원 | 가져올 파일을 제외하면 나머지 파일로 계획을 다시 계산한다. 실패한 파일은 같은 선택으로 재시도할 수 있다. ZIP 복원은 미리보기에서 확인한 작품만 교체하고, 복원 후 서재 조회가 실패하면 목록만 다시 읽는다. |
| 메모와 번역 | 메모를 저장하는 중에 덧쓴 내용은 다음 수정에 남긴다. 번역 작업의 상태 조회가 회복되면 서버가 확인한 결과를 표시한다. 번역 키를 저장한 뒤 설정 조회만 실패하면 재시도 시 키를 다시 보내지 않는다. |

## 검증 범위

격리된 브라우저에서 합성 TXT·EPUB의 읽기, 화면 전환, 선택 도구, 낭독 재시도와 다운로드 복구를 검증했다. 호스팅 시작 검사는 390px·820px Chromium에서 첫 로그인과 인증을 유지한 새로고침을 실행한다. 기기의 음성 목록이 늦거나 조회에 실패해도 서재를 사용할 수 있어야 한다. 회차 끝의 약한 입력과 새로 시작한 스와이프는 Chromium과 WebKit에서 각각 확인했다.

개발 중 전체 클라이언트·공유 패키지 검사에는 PDF 작성자 대소문자, 구형 해시 사용처 검사, Node 렌더링 시 브라우저 전역 참조에 관한 기존 실패가 있었다. 서버 전체 검사는 계정·소유권 테스트 대역과 오디오북 작업의 동시 실행에 따른 실패가 포함되어 집중 회귀 검사와 결과가 달랐다. 실제 Android·iPhone의 화면 잠금, 블루투스 전환, 기기 음성과 유료 제공자 재생은 별도 기기 검증이 필요하다.

## 다음 성능 측정

- **큰 서재** — 합성 서재 열기는 20권에서 61~74ms, 1,000권에서 약 1.2초였다. 사용하는 기기와 서재 규모에서 렌더링 시간을 다시 재고, 화면 밖 카드를 줄일 때 스크롤 위치와 포커스 복원도 확인한다.
- **가져오기와 저장** — 32MiB 파일 해시와 합성 TXT 24화 조립에서 구현별 차이가 관찰됐다. 파일 선택부터 준비 완료, 다운로드부터 첫 회차 열기까지 측정하고 취소·재개를 함께 검증한다.
- **회차와 듣기** — 스트리밍 이어 읽기, EPUB 듣기, 만화 첫 장, 다음 회차 자동 번역에서 목차·본문·이미지 요청 횟수와 첫 화면·첫 소리까지의 시간을 잰다. 긴 만화는 스크롤 프레임 시간도 확인한다.
- **화면과 네이티브 코드** — 상세 문구·메뉴·필터·모션을 바꿀 때는 구체적인 조작 불편을 먼저 재현한다. C 등 네이티브 구현은 중복 작업과 입출력 대기를 줄인 뒤에도 CPU 프로파일에서 비용이 큰 구간을 대상으로 비교한다.
