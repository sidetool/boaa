# 텍스트 작품 번역 구현 계획

> 2026-10-19: 서버 웹/PWA의 첫 구현을 추가했다. 실제 지원 범위·운영·검증은 [작품 번역 구현 문서](../text-translation.md)를 기준으로 한다. 아래는 전체 확장 계획이며, 작품별 용어집·회원 권한·번역 TTS 등 후속 항목도 포함한다.

상태: 제안 단계. 2026-10-19 코드 확인 기준이며 아직 구현·DB 변경·외부 번역 호출·운영 배포는 하지 않았다.
대상: BOAA 서버 웹/PWA. UI는 기존 설정 페이지, PrefSection/PrefGroup/PrefFold, 리더의 보조 화면과 상태 표시를 따른다. 별도 디자인 체계를 만들지 않는다.

## 1. 사용자 동작과 기본값

- 설정에 독립된 **작품 번역** 메뉴를 추가한다. 서비스 기본값은 비활성화다.
- 관리자가 엔진·모델·키를 연결하고 번역을 켠다. 이 동작만으로 서재 전체를 번역하지 않는다.
- 번역 실행 방식은 **버튼으로 시작**(기본) / **외국어 작품을 열면 자동**이다. 작품별로 전역값 따르기·자동·수동·번역 안 함을 지정한다.
- 목표 언어는 한국어가 기본이다. 대상은 TXT·EPUB 및 소스의 텍스트 회차다. 이미지 만화·스캔 PDF/OCR는 제외한다. 서버가 읽을 수 없는 기기 전용 파일은 서버로 가져온 뒤 사용한다.
- 작품 언어와 목표 언어가 다를 때 번역 제어를 표시한다. 언어를 확정할 수 없으면 유료 자동 요청 대신 언어 선택/수동 번역을 제공한다.
- 작품 언어는 신뢰 가능한 메타데이터 → 로컬 언어 감지 → 사용자 지정 순서로 결정한다. 사용자 지정이 최우선이다. 감지 결과는 원문 버전에 묶어 저장한다.
- 감지는 본문의 여러 구간에서 표본을 뽑고 공백·구두점·URL·목차 같은 잡음을 제외한다. 한자 비율만으로 한국어/일본어/중국어를 단정하지 않는다. 혼합 언어·낮은 신뢰도에서는 자동 번역하지 않는다.
- ‘번역 보기 / 원문 보기’를 즉시 전환한다. 이미 저장된 번역을 열거나 보기만 바꾸는 동작은 API를 다시 호출하지 않는다.
- 본문이 바뀌어도 원문을 덮어쓰지 않는다. 회차·문단 ID, 읽기 기록, 표지, 원본 파일, 다운로드 상태는 그대로 둔다.

권장 초기값(운영 모델에 맞춘 성능 검증 후 확정):

| 설정              | 기본                            | 조절 범위/의미                                                               |
| ----------------- | ------------------------------- | ---------------------------------------------------------------------------- |
| 번역 서비스       | 끔                              | 서버 공통 기능 스위치                                                        |
| 실행 방식         | 버튼으로 시작                   | 자동은 별도 선택                                                             |
| 목표 언어         | 한국어                          | 지원 언어 목록과 원문 언어 수동 지정                                         |
| 작업 단위         | 화                              | 한 화를 하나의 논리 작업으로 관리                                            |
| 요청 분할         | 화 단위, 모델 한도 초과 시 분할 | 고급에서 문단 묶음 선택; 2,000~12,000자, 권장 6,000자; 토큰 한도가 항상 우선 |
| 동시 외부 요청    | 1                               | 최대 3, 엔진/계정/서버 한도 적용                                             |
| 다음 화 미리 번역 | 1화                             | 끔 또는 1~3화, 현재 읽는 작품에만 적용                                       |
| 재시도            | 최초 요청 후 최대 3회           | 0~5회; 자동 형식 복구도 총 시도 예산에 포함                                  |
| 지수 백오프       | 시작 2초, 배수 2, 상한 60초     | 지터 적용; 공급자 Retry-After가 더 길면 그 시간을 우선                       |
| 요청 제한 시간    | 120초                           | 고급에서 30~300초; 작업 전체 자동 대기는 기본 10분 상한                      |

‘화 단위’는 기본 사용 단위이며 무조건 화 전체를 단일 HTTP 요청에 넣는다는 뜻은 아니다. 입력과 예상 번역 출력이 모델 한도를 넘으면 문단 경계로 분할한다. TTS의 700자 제한을 번역에 그대로 적용하지 않는다.

## 2. UI/UX

설정의 ‘작품 번역’에서 다음을 제공한다.

- 상단: 기능 사용, 연결 상태, 목표 언어, 자동/수동 실행 방식.
- 엔진 연결: 기존 ProviderSettingsPanel의 형태를 재사용한다. 엔진·모델 선택, API 키/Vertex JSON 저장·교체·삭제, 연결 확인. 인증 저장 확인과 실제 유료 번역 시험은 구분한다.
- 읽기 준비: 다음 화 미리 번역 수. 자동 번역과 사전 번역이 외부 호출을 발생시킨다는 짧은 설명을 둔다.
- 고급 접기: 요청 분할 크기, 동시성, 재시도·백오프·시간 제한. 일반 화면에는 숫자 설정을 늘어놓지 않는다.
- 용어집: 이름/용어와 번역을 작품별로 지정한다. 공통 용어집도 지원하고 작품별 항목이 우선한다. 초기는 추가·수정·삭제와 짧은 문체 지침만 제공한다.
- 저장된 번역: 작품별 준비된 회차 수와 사용 용량, 번역만 삭제, 선택 회차 재번역. 재번역 시 비용 발생과 변경 범위를 알린다.

리더에서는 기존 상단 더보기/보조 시트에 ‘번역’을 배치하고, 대상 작품에서만 원문/번역 전환과 현재 상태를 표시한다. 매 화 모달을 띄우지 않는다.

- 첫 실행에서 외부 API로 본문을 전송하며 비용이 생길 수 있다는 점과 다음 화 준비 범위를 확인한다. 이후 동일 정책의 연속 읽기에는 반복 확인하지 않는다.
- 수동 시작 시 ‘현재 화부터 번역하며 읽기’는 설정된 다음 화 준비를 사용한다. ‘이번 화만’은 사전 번역 없이 현재 화만 처리한다.
- 상태: 준비 중 / 번역 중 n/N문단 / 다음 화 준비 중 / 할당량 대기·재시도 시각 / 완료 / 실패·다시 시도 / 취소.
- 준비된 문단은 바로 보여주고, 아직 준비되지 않은 문단은 원문과 작은 상태 표시로 둔다. 긴 로딩 화면으로 회차 전체를 가리지 않는다.
- 읽는 위치보다 앞선 문단이 교체될 때 스크롤이 튀지 않도록 원문 문단 앵커를 보존한다. 가상 목록 높이를 다시 측정하고 페이지 모드도 재계산한다.
- 화 이동·원문 전환·폰트 변경·백그라운드 복귀에도 표시 버전과 읽기 위치가 뒤섞이지 않게 한다.
- 재번역은 새 버전이 준비될 때까지 기존 완성본을 유지한다. 현재 듣기 중인 문단은 교체하지 않고 명시적으로 재생을 재시작할 때 새 버전을 쓴다.

## 3. 먼저 보여주기와 다음 화 준비

1. 원문에 대한 접근 권한과 서버 기능/사용자 권한을 확인한다.
2. 원문 버전·언어·번역 프로필로 저장 결과를 조회한다. 같으면 즉시 재사용한다.
3. 없으면 중복 실행을 막는 작업을 등록한다. 현재 화 > 사용자가 직접 요청한 화 > 다음 화 준비 순으로 우선한다.
4. 모델에 문단 ID와 본문을 구조화해 전달한다. 출력도 문단 ID별 번역으로 받는다.
5. 스트리밍을 지원하는 엔진은 **완성되고 검증된 문단**부터 서버에 저장하고 UI에 전달한다. 미완성 JSON이나 토큰 조각을 그대로 본문에 붙이지 않는다.
6. 엔진이 부분 구조 출력에 적합하지 않으면 문단 묶음별로 완료 결과를 전달한다. 동일한 UI 상태/저장 계약을 사용한다.
7. 서버 저장 이벤트는 작업 ID·문단 ID·순서 번호를 가진다. SSE 재연결 시 저장된 결과/이벤트를 다시 읽으며 폴링으로도 복구할 수 있다. 연결이 끊겼다고 번역 API를 다시 호출하지 않는다.
8. 활성 번역 세션에서 현재 화가 읽을 수 있게 준비되면 다음 화를 저우선순위로 예약한다. 기본 동시성 1에서는 현재 화 작업을 먼저 끝내고 실행한다. 완료된 다음 화가 또 다음 화를 예약하는 연쇄 동작은 금지한다.

앱에서 다른 작품으로 이동하면 불필요한 대기 중 사전 번역은 취소한다. 다음 화 준비는 서버가 이미 확인한 다음 회차 식별자를 사용하고, 기존 계정별 소스 접근/프록시/로그인 경계를 그대로 따른다. 본문을 얻을 수 없는 다음 화는 ‘본문 준비 필요’로 표시하며 구매·로그인이나 무제한 소스 수집을 자동 수행하지 않는다.

일시적인 모바일 연결 끊김에는 현재 접수된 화와 이미 예약된 제한된 사전 번역만 마칠 수 있다. 사용자 취소, 기능 끄기, 권한 회수 시 새 호출을 막고 진행 중 요청은 가능한 범위에서 중단한다. 이미 공급자에게 전달된 요청의 비용까지 취소된다고 보장하지 않는다.

## 4. 프로바이더와 인증

- 초기 목표: Gemini API, Gemini Vertex(JSON/서버 자격 증명), OpenAI 호환 텍스트 생성 endpoint. 기존 Anthropic 연결은 같은 어댑터 규약을 확립한 뒤 추가한다.
- 모델명은 임의의 고정 최신 버전으로 가정하지 않는다. 연결별 지원 모델과 스트리밍·구조화 출력·입출력 토큰 한도를 검증한다.
- 현재 `AIProvider`는 화자 분석용 메서드가 중심이다. 번역을 분석 요청으로 위장하지 않고 `TranslationProvider`와 `text_translation` 설정/secret scope를 추가한다. HTTP 인증·타임아웃·오류 분류·공급자 실행 메타데이터는 재사용한다.
- 번역 설정 변경이 TTS/화자 분석의 모델·키·옵션을 바꾸지 않도록 분리한다. 기존 저장 키를 쓰려면 사용자가 명시적으로 연결을 선택한다.
- 현재 웹/PWA는 OS 키체인에 API 키를 직접 저장하는 방식으로 설계하지 않는다. 키는 기존 서버의 암호화 secret 저장소에 보관하고 클라이언트에는 연결 여부/마스킹 정보만 돌려준다. 브라우저 localStorage·로그·작업 payload에 원문 키를 저장하지 않는다.
- Vertex JSON은 기존 파일 읽기 race 방지, 크기/형식 검증, 암호화 저장, 토큰 발급 helper를 재사용한다. 현재 JSON 허용 조건이 TTS에 한정돼 있으므로 번역 scope와 권한을 별도로 확장한다.
- 데스크톱을 나중에 지원하면 기존 OS secret/keychain 어댑터와 연결할 수 있도록 저장 포트는 분리하되, 이번 서버 웹 기능에 데스크톱 구현을 포함하지 않는다.
- 사용자 endpoint는 관리자만 설정하고 기존 로컬 endpoint/egress 정책으로 검증한다. 인증 헤더가 리다이렉트나 다른 호스트에 전달되지 않도록 한다.

## 5. 서버 저장과 원문 경계

번역은 원문과 별도의 파생 데이터다. 초기에는 PostgreSQL에 메타데이터와 문단별 번역을 저장한다. 번역 텍스트가 너무 커지는 경우 객체 저장소 분리는 이후 측정에 따른다. 대형 런타임/새 컨테이너는 추가하지 않는다.

제안 테이블/계약(명칭은 구현 시 기존 규약에 맞춘다):

- `translation_settings`: 서버 활성화/상한, 계정 기본값, 작품별 override. 서버 정책과 계정 취향을 다른 레코드로 구분한다.
- `translation_glossaries`: owner, 작품 범위, 용어/번역, revision.
- `translation_documents`: owner, 원문 종류/식별자, 원문 revision/hash, 소스/목표 언어, provider/model, 프로필 hash, 상태, 생성 버전.
- `translation_segments`: document/version, 안정된 원문 문단 ID, 순서, source hash, 번역문, 상태. 같은 문단 결과는 idempotent하게 기록한다.
- 작업 실행/attempt/lease/사용량 기록은 기존 provider job 기반을 확장한다. 새 UI용으로 서버 실행기를 중복 구현하지 않는다.

캐시 키는 **소유 계정 + 원문 정체성 + 원문 revision/hash + 목표 언어 + provider/model + 프롬프트 버전 + 용어집/문체 revision**을 포함한다. 같은 입력에 대한 여러 탭의 요청은 하나로 합친다. 다른 계정끼리 제목/본문 hash가 같다는 이유로 결과나 원문을 공유하지 않는다.

소스 스트리밍 회차에는 로컬 책 ID가 없을 수 있다. 책/chapter ID뿐 아니라 소스·계정 연결·작품·회차 식별자와 서버가 확인한 본문 hash를 수용하는 원문 참조를 만든다. 계정 소유권이 확인된 본문 snapshot을 사용하며, 클라이언트가 보낸 임의 URL을 서버가 번역 명목으로 가져오지 않는다. 나중에 다운로드된 책과 연결될 때도 동일 계정·동일 본문임이 검증된 경우에만 결과를 재사용한다.

원문 수정·재수입·재분할·용어집 변경 시 기존 번역을 새 원문용으로 오인하지 않는다. 구버전 표시와 재번역 선택을 제공하고, 비용이 드는 서재 전체 재번역은 자동 실행하지 않는다. 결과 커밋 시 owner와 원문 revision을 다시 확인해 삭제·변경된 작품에 늦은 결과가 붙지 않게 한다.

휴지통 이동은 원문/번역을 함께 숨기고 복원 가능하게 둔다. 번역만 삭제는 원문/표지/읽기 기록에 영향을 주지 않는다. 작품 영구 삭제·계정 삭제는 해당 번역/원문 snapshot/대기 작업까지 정리한다. 백업에는 번역 데이터 포함 여부와 원문 연결 복원을 정의하되 외부 API 키는 개인 내보내기에 포함하지 않는다. 서버 전체 백업에서 암호화 secret과 복호화 키는 기존 복구 경계를 유지한다.

## 6. 할당량·재시도·결과 검증

- 429, 일시적인 5xx, 네트워크/시간 초과는 제한된 재시도 대상으로 분류한다. Retry-After/공급자 retryDelay와 지수 백오프·지터를 적용한다.
- 인증/권한/잘못된 모델/소진된 일일 할당량/안전 정책 차단은 무한 재시도하지 않는다. 원인과 조치를 안내하고 사용자가 다시 시작할 수 있게 한다.
- SDK 내부 재시도와 BOAA 작업 재시도를 중첩시키지 않는다. 실제 외부 호출 횟수 기준으로 총 예산을 관리한다.
- 키/프로젝트·모델별 RPM/TPM과 동시성을 서버 전체에서 합산한다. 같은 결제 프로젝트의 여러 키로 한도를 우회하지 않는다. 공급자 한도는 모델·계정마다 다르므로 보편적인 RPM 값을 가정하지 않는다.
- 현재 읽기/TTS 요청이 사전 번역 때문에 굶지 않도록 엔진별 공유 예산과 작업 우선순위를 둔다. 다른 키/엔진까지 무조건 직렬화하지는 않는다.
- 추정 토큰과 실제 사용량, 실패/재시도 횟수를 기록한다. 일일 토큰/요청 한도와 남은 예산 확인을 제공한다. 요청 전 예약·완료 후 정산하고, 가격표가 확인되지 않은 비용을 정확한 원화로 표시하지 않는다.
- 다른 엔진으로 유료 자동 전환하지 않는다. 실패 시 엔진 변경은 명시적 사용자 선택이다.
- 문단 ID의 누락·중복·순서·빈 결과·잘린 응답을 검증한다. 공백 문단은 비용 없이 유지한다. 실패한 범위만 재시도하며 정상 저장된 문단을 무작정 재요청하지 않는다.
- 원문과 번역문은 신뢰할 수 없는 콘텐츠로 취급한다. 번역 모델에는 도구 실행 권한을 주지 않고 본문 속 지시를 따르지 않게 분리한다. HTML/Markdown 실행 대신 안전한 본문 표현으로 렌더링한다.
- EPUB 주석·루비·링크는 원문 참조를 유지하고 번역용 텍스트/보존 토큰으로 처리한다. 텍스트가 없는 구조를 임의 번역하거나 ID를 모델에게 새로 만들게 하지 않는다.

공식 문서 근거: [Gemini 오류 처리](https://ai.google.dev/gemini-api/docs/troubleshooting), [할당량](https://ai.google.dev/gemini-api/docs/rate-limits), [구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output). 구조화 출력은 스키마의 일부만 지원하므로 실제 선택 모델별 검증이 필요하다.

## 7. 다중 계정·읽기 기록·TTS

- 서버 전체 활성화/엔진/키/한도는 관리자 전용. 기본은 관리자만 번역 호출 가능하다.
- 회원에게 열 경우 `useTranslation`을 독립 capability로 명시적으로 허용한다. 기존 `useProviders`를 통째로 열어 서버 TTS·AI 설정 권한까지 주지 않는다. 이 경우에만 관리자의 번역 연결로 작업할 수 있고 회원별 예산을 적용한다.
- 회원에게 연결 비밀 값은 반환하지 않는다. 결과·설정·작업 조회는 owner별로 검증한다. 계정 이용 중지/소스 허용 해제는 대기 작업 및 다음 호출에 반영한다.
- 현재 읽기 위치는 원문 문단 ID + 원문/번역 표시 모드 + 필요한 번역 버전으로 연결한다. 번역문 글자 수가 달라져도 원문 회차 진행률을 다시 산정하거나 읽음 회차 수를 늘리지 않는다.
- 화면 검색은 선택한 표시 모드의 준비된 본문을 대상으로 하고, 미번역 구간은 원문임을 표시한다. 서버 전체 번역문 전문 검색 인덱스는 초기 범위 밖이다.
- 일반 TTS는 사용자가 번역을 보고 있을 때 준비된 번역문을 읽을 수 있게 한다. 낭독 스냅샷/캐시에 번역 버전·실제 발화 텍스트 hash를 넣고, 기존 발음 필터는 번역문에 적용한다.
- 미번역 문단을 만나면 기다림/원문으로 읽기를 명시적으로 선택하게 한다. 번역과 원문을 조용히 섞어 재생하지 않는다. 화자 분리 기능과는 독립적으로 구현한다.

## 8. 구현 순서와 완료 조건

1. **도메인·저장·접근 제어**: 원문 참조/번역 프로필/상태 계약, additive DB migration, 소유권 검증, 비활성화 기본값. 기존 데이터·리더에 영향 없는 상태를 먼저 만든다.
2. **단일 화 번역 경로**: Gemini adapter, 원문 snapshot, job/lease/idempotency, 문단 검증·저장, 수동 번역·취소·조회. mock으로 재시도/제한/중복 경계를 검증한다.
3. **설정·리더 표시**: 기존 설정 메뉴에 자연스럽게 통합, secret 연결, 원문/번역 전환, 언어 판단/수동 override, 문단 도착에 따른 위치 보존. 실제 모바일·데스크톱 폭에서 확인한다.
4. **연속 읽기·성능**: 부분 응답, 복구 가능한 SSE, 다음 화 예약, 순서 변경/취소, 할당량 조절, 일반 TTS 번역문 연결. 읽는 화 우선 처리와 제한된 선행 범위를 검증한다.
5. **추가 연결·운영**: Vertex JSON·OpenAI 호환 연결, 용어집/사용량/삭제/백업, 회원 선택 허용. 기존 운영과 분리된 환경에서 DB와 업데이터 호환성을 검증한 뒤 배포한다.

필수 검증:

- 서비스 꺼짐·한국어 작품·권한 없음·언어 불확실 상태에서 원치 않는 유료 호출 0회.
- 수동/자동/이번 화만, 설정 재로그인·기기 변경 시 저장 범위, 원문/번역 즉시 전환.
- 동일 화 중복 탭, 앱 재시작, worker crash, SSE 재연결, 늦은 결과, 부분 성공·재시도에서 결과 혼합과 무제한 중복 청구 방지.
- 429/503/타임아웃/인증 실패/정책 차단, 재시도 소진과 사용자 재개. 실제 요청 수·대기 시간·공유 예산 검증.
- 장문·빈 문단·한중일 혼합·EPUB 주석, 출력 누락/중복/잘림, 원문 변경·삭제와 번역 커밋 경쟁.
- 스트리밍→다운로드, 회차 번호/읽기 기록/표지/북마크 유지. 회원·소스 로그인/계정 전환 격리.
- 390px와 데스크톱, 긴 문단 가상 스크롤, 글자 크기 변경, 부분 번역 도착/배경 복귀/TTS 추적에서 겹침·위치 튐 없음.
- 새 데이터의 전체 백업·복원, 번역만 삭제, 기존 데이터 보존과 직전 웹/서버 버전 호환 검증. 스키마 epoch/자동 롤백 허용은 실제 migration 검증 후 결정한다.
- 최종 소량 실 API 시험은 지정된 엔진/키로 실행한다. 호출·사용 토큰을 기록하고 자동으로 전체 작품을 시험하지 않는다.

진행 원칙: 위 전체 범위를 한 번에 운영에 켜지 않는다. 비활성 상태로 구현하고 격리 환경 검증 후 관리자에게 먼저 활성화한다. 첫 화면 표시 시간/한 화 완료 시간/호출 수는 실제 대상 모델로 측정하며 숫자를 미리 보장하지 않는다.

## 9. 코드 연결 지점

- `src/features/reader-settings/settings-panel-contract.ts`, `src/ui-next/settings/pages/`: 작품 번역 메뉴/설정 화면.
- `src/features/providers/`, `apps/server/src/providers/server-provider-settings.ts`, `server-provider-secrets.ts`: 번역 scope와 연결 설정/암호화 저장.
- `apps/server/src/providers/*`, `src/providers/`: 별도 번역 port와 공급자 adapter; 기존 분석용 AIProvider의 의미를 유지한다.
- `apps/server/src/routes/ai/`, `apps/server/src/services/provider-jobs/`: 번역 작업 등록/실행/재시도/lease/usage 확장. 공통 관리자 전용 hook에 회원 경로가 우발적으로 묶이지 않도록 별도 route 경계를 검토한다.
- `apps/server/src/db/migrations/`, 서버 저장 repository: 번역 문서/문단/프로필과 계정별 제약.
- `src/features/reader/ReaderViewport.tsx`, 리더 repository/본문 projection, `src/features/external-sources/`: 원문을 보존한 번역 표시·스트리밍 회차 연결.
- `src/features/tts/`, plain TTS 캐시/입력 생성: 표시 번역 버전과 발화 경계.

후속 확장: 전체 작품 일괄 번역, 공유 번역본/공유 비용 계정, 직접 번역문 편집과 내보내기, 데스크톱 OS 키체인, PDF/OCR는 별도 작업으로 둔다.
